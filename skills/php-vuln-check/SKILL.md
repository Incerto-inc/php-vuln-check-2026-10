# PHP の脆弱性の確認(読むだけ)

## 守ること

- **何も変更しない。** ファイル・設定の変更、PHP の更新、サービスの再起動、パッケージの入れ替えはしない。直すのが良さそうでも、提案だけにして、必ず人に確かめる
- **外部に送らない。** 結果はこの会話の中だけで扱う
- sudo や管理者の権限は使わない(人が明示して頼んだときだけ)

## 手順

1. OS を確かめる(`uname -s`、Windows なら `$PSVersionTable`)
2. このスキルのフォルダ(読み込んだときに示される Base directory)にある確認のコマンドを実行する
   - Linux・Mac: `bash "<Base directory>/php-check.sh"`
   - Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File "<Base directory>\php-check.ps1"`
3. 結果を、次の表に当てはめて日本語でまとめる

| 結果の表示 | まとめ方 |
| --- | --- |
| `対象です` / `AFFECTED` | 「この PHP は更新が必要」。どの版へ上げるか(8.2.35 / 8.3.36 / 8.4.27 / 8.5.12) |
| `修正済み` / `FIXED` | 「対応済み」 |
| `サポートが終わった版` / `END OF LIFE` | 「修正版が出ない。サポート中の版へ上げる必要がある」 |
| `OS の部品として入った PHP` | 「版の番号では判断できない。OS の更新と提供元のセキュリティ情報を確かめる」 |
| `php_module` / `mod_php` | 「Apache 組み込みで動いている。開発元の告知では影響がいちばん大きい形。更新を急ぐ」 |
| `session.upload_progress.enabled => On` | 「更新までのつなぎとして Off にする緩和がある(更新の代わりにはならない)。変える前に管理者と相談」 |

4. 最後に、次の3つを短く書く
   - 更新が要る PHP の一覧(場所と今の版)
   - 確かめきれなかったこと(権限が足りない場所、レンタルサーバーのサイトなど)
   - 次にすること(誰に何を頼むか)。**自分では直さない**

## 注意

- レンタルサーバー(共用)の上のサイトは、このコマンドで出る版とサイトが使う版が違うことがある。サイトの版は、サーバー会社の管理画面か WordPress の「ツール → サイトヘルス → 情報 → サーバー」で確かめるよう伝える
- 修正版の番号と対象は、開発元の告知が正本: https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w / https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp
